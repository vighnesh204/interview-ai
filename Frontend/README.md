## 🌟 Overview

**Interview AI** is a full-stack web application that acts as a personal career coach. Instead of generic interview preparation, it reads your actual resume and the specific job description you're applying for — then uses **Google Gemini AI** to generate a completely tailored interview strategy.

### What problem does it solve?

Most developers send the same resume everywhere and prepare with generic resources. Interview AI bridges the gap by providing:

- A **match score** showing how well your profile fits the role
- **Technical & behavioral questions** the interviewer is likely to ask — based on *your* resume and *their* JD
- **Skill gap analysis** with severity levels (low / medium / high)
- A **day-wise preparation roadmap** to close those gaps before the interview
- A **tailored resume PDF** generated by AI, optimized for both ATS systems and the specific role

## 🏗 Architecture

The backend follows a clean **4-layer architecture**:

```
Request → Routes → Controllers → Services → Models → Database
                                          ↗
                               (AI Service)
```

| Layer | Files | Responsibility |
|-------|-------|---------------|
| **Routes** | `*.routes.js` | Define HTTP methods + paths, apply middleware chain |
| **Controllers** | `*.controller.js` | Handle req/res, orchestrate service calls, return responses |
| **Services** | `ai.service.js` | Heavy business logic — Gemini API calls, PDF generation |
| **Models** | `*.model.js` | Mongoose schemas, DB interaction |

The frontend uses a **feature-based structure** with each feature (auth, interview) owning its own context, hooks, pages, and services — keeping concerns cleanly separated.

## 🚀 Getting Started

### Prerequisites

- Node.js v18+
- MongoDB (local or Atlas)
- Google Gemini API key ([get one here](https://aistudio.google.com/))

### 1. Clone the repository

```bash
git clone https://github.com/your-username/interview-ai-yt.git
cd interview-ai-yt
```

### 2. Setup Backend

```bash
cd Backend
npm install
```

Create a `.env` file in the `Backend/` directory (see [Environment Variables](#-environment-variables)):

```bash
cp .env.example .env   # or create manually
```

Start the backend dev server:

```bash
npm run dev
# Server running on http://localhost:3000
```

### 3. Setup Frontend

```bash
cd ../Frontend
npm install
npm run dev
# App running on http://localhost:5173
```

> Both servers must be running simultaneously for the app to work.

## 🔄 Data Flow

### Generating an Interview Report

```
User clicks "Generate" (Home.jsx)
    │
    ▼
useInterview.js → generateReport()
    │
    ▼
interview.api.js → POST /api/interview/
    │   (FormData: resume PDF + jobDescription + selfDescription)
    │   (Cookie with JWT sent automatically via withCredentials: true)
    │
    ▼
Backend: auth.middleware.js → verifies JWT from cookie
    │
    ▼
Backend: file.middleware.js (Multer) → stores PDF in memory buffer
    │
    ▼
Backend: interview.controller.js
    │   → pdf-parse extracts text from req.file.buffer
    │   → calls generateInterviewReport() in ai.service.js
    │
    ▼
Backend: ai.service.js ⭐ (Core AI Logic)
    │   → Zod schema defines exact JSON structure needed
    │   → zodToJsonSchema() converts it for Gemini API
    │   → Gemini 2.5 Flash generates structured JSON response
    │   → JSON.parse(response.text) returns clean object
    │
    ▼
Backend: interviewReportModel.create() → saved to MongoDB
    │
    ▼
Response → useInterview.js → setReport() → InterviewContext updated
    │
    ▼
navigate('/interview/:id') → Interview.jsx renders the report
```

### Generating a Resume PDF

```
User clicks "Download Resume" (Interview.jsx)
    │
    ▼
useInterview.js → getResumePdf(interviewId)
    │
    ▼
interview.api.js → POST /api/interview/resume/pdf/:id
    │   (responseType: "blob" — expects binary PDF)
    │
    ▼
Backend: interview.controller.js
    │   → fetches stored report from MongoDB
    │   → calls generateResumePdf() in ai.service.js
    │
    ▼
Backend: ai.service.js
    │   → Gemini generates professional HTML resume as JSON {html: "..."}
    │   → generatePdfFromHtml() launches Puppeteer (headless Chrome)
    │   → page.setContent(html) → page.pdf() → PDF buffer
    │   → browser.close()
    │
    ▼
Response: Content-Type: application/pdf sent as binary
    │
    ▼
Frontend: Blob → createObjectURL → <a>.click() → browser downloads file
```

## 🧠 Key Design Decisions

### Why Zod for AI responses?

Gemini API supports `responseSchema` — when combined with a Zod-defined schema converted via `zodToJsonSchema()`, the AI is **forced to return structured JSON** matching your exact schema. This eliminates unpredictable AI output and removes the need for manual response parsing/validation.

```js
// ai.service.js — schema acts as a contract with the AI
const interviewReportSchema = z.object({
  matchScore: z.number(),
  technicalQuestions: z.array(z.object({
    question: z.string(),
    intention: z.string(),
    answer: z.string()
  })),
  // ...
})

await ai.models.generateContent({
  config: {
    responseMimeType: "application/json",
    responseSchema: zodToJsonSchema(interviewReportSchema)  // AI must match this
  }
})
```

### Why `memoryStorage()` for Multer?

PDF files are uploaded, parsed for text, and **never stored on disk**. Using `multer.memoryStorage()` keeps the file in RAM as a `Buffer` (`req.file.buffer`), passed directly to `pdf-parse`. This avoids disk I/O and the need to clean up temporary files.

### Why Token Blacklisting?

JWTs are stateless — once issued, they're valid until expiry even after logout. The `blacklistTokens` MongoDB collection stores invalidated tokens on logout. Every protected request checks this collection first. The `timestamps: true` option on the schema enables future TTL-based auto-cleanup.

### Why Feature-Based Frontend Structure?

Each feature (`auth`, `interview`) is completely self-contained with its own context, hooks, pages, and services. This means:
- Adding a new feature = adding a new folder, no existing files touched
- Each feature's Axios instance, state, and logic are co-located
- Easy to understand, easy to scale

## 🔒 Authentication Flow

```
Register/Login
    → password hashed with bcrypt (10 rounds)
    → JWT signed with JWT_SECRET (expires: 1d)
    → token set as cookie (res.cookie)

Protected Request
    → auth.middleware.js reads req.cookies.token
    → checks blacklistTokens collection (401 if found)
    → jwt.verify() validates signature
    → req.user = { id, username } attached for controllers

Logout
    → token added to blacklistTokens
    → res.clearCookie('token')
```
